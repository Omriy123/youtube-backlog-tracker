# Track tasks in GitHub and keep durable design in the repository

Development uses GitHub Issues for task scope, acceptance criteria, dependencies, and discussion, with branches and pull requests for implementation. The spec, glossary, decisions, research, and accepted layout feedback remain Markdown files versioned alongside the code so changes are reviewable together. This replaces the initial local Markdown tracker under `.scratch/`, which remains an ignored workspace for temporary artifacts; maintaining two active trackers would let status and requirements diverge across sessions.
